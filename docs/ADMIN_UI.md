# ממשק הניהול של הנעילה (תוסף "הגדרות מערכת", טאב "מצב נעילה")

קובץ: `system-settings/js/sections/kiosk.js`. סגנונות: `system-settings/css/app.css` (בלוק "בריאות ההקשחה ומרכז חירום"). אנגלית: `system-settings/js/lang-en.js`.

## סדר הטאב

1. כרטיס מצב (פעיל / לא פעיל / פתוח זמנית) עם כפתורי ההפעלה והביטול.
2. **בריאות ההקשחה**: לוח מצב בשפה פשוטה (חדש).
3. **מרכז חירום**: צעדים ברורים לשחרור נעילה (חדש).
4. ריבוע אחד של הסברים מתקפלים.
5. סיסמה והגדרות, הגדרות נעילה, תוכנות מותרות.
6. ריבוע אחד "חיבורים, הקשחה ושחזור" (תוספים מחוברים, רכיב הקשחה, BIOS).

## לוח "בריאות ההקשחה"

כל שורה מציגה אייקון, כותרת, משפט הסבר ותווית מילולית (תקין / שימו לב / דורש טיפול / לא זמין), כך שהרמה לא תלויה בצבע בלבד.
שדה שהגשר לא חושף מוצג כ"לא זמין" (בעדינות, בלי שגיאה). כותרת הלוח מסכמת לפי הרמה הגרועה ביותר.

| שורה | מקור ב-API | הערות |
|---|---|---|
| רכיב ההקשחה (שירות) | `POST /kiosk/status` ← `hard.installed`, `hard.running`, `hard.needsUpdate` | קיים |
| נעילה | `active`, `tempUnlock.active`, `schedule.enabled/start/end` | קיים |
| אכיפת הנעילה | `hard.enforcementIssues` (או `enforcementIssues`) | נחשף: מערך קודים (`unverified`/`error`). `null`/חסר (שירות לא עונה או ישן): "לא זמין". |
| קובץ ההגדרות | `hard.stateCorrupt`, `hard.configSealOk` (או ברמה העליונה) | נחשפים (בוליאנים; `null` = לא ידוע). |
| קוד שחזור | `hard.hasRecovery`, ובגיבוי `recoverySaved` מ-`/kiosk/status` | שניהם קיימים. |
| קודי גיבוי | `POST /kiosk/recovery/backup/status` ← `left` (גיבוי: `hard.backupLeft`) | קיים |
| הקשחת אתחול (Safe Mode / WinRE) | `POST /bios/status` ← `boot.enforcement.active/incomplete`, `boot.error` | קיים |
| תקינות עדכון אחרון | `hard.updateHealth` (`ok`/`rollback`/`state`) | נחשף: `{state, ok, pending, rollback}`. |
| גרסת הגשר | `hard.version` או `GET /health` ← `version` | קיים |

הוספת השדות החסרים ל-`HardLock.Status()`/`/kiosk/status` בצד הגשר תדליק את השורות האלה אוטומטית, בלי שינוי בממשק.

מצב נעילת סייר הקבצים בשורה "נעילת סייר הקבצים" נקרא ישירות מ-`POST /fs/policy/get` ← `effective` (בלי להחליף טאב).

## מרכז חירום

הסבר קצר וחמישה צעדים: קוד שחזור בחלון הביטול, קיצור `Ctrl+Alt+Shift+F12` (עם `Fn` במחשבים ניידים), 7 לחיצות על השעון, `OtzariaBridge.exe --unlock <קוד-שחזור>`, ו-Safe Mode כמוצא אחרון.
לא מוצג שום קוד או סיסמה. כפתורים: העתקת פקודת השחזור (תבנית בלבד), רענון מצב, יצירת קודי גיבוי (דורש סיסמה, הקודים מוצגים רק בחלון היצירה).

## הודעות שגיאה

`friendlyErr` (בקובץ הטאב) ממיר שגיאות רשת/503/fail-closed/פנימיות למשפט קצר עם "מה לעשות". `wrong_password`, `locked` ו-`too_many` נשארים כפי שהגשר מחזיר (כוללים זמן המתנה). כל קריאות הגשר של הטאב עוברות דרך `bcall` שמחילה זאת, כך שגם חלונות הדיאלוג מציגים הודעה ידידותית.

## בדיקה חיה ב-VM

- פתיחת הטאב עם גשר בלי שירות הקשחה, עם שירות רץ, עם שירות לא רץ, ועם שירות ישן (`needsUpdate`).
- הפלת הגשר באמצע טעינה: הודעת "הגשר לא זמין" עם "נסה שוב".
- ניגודיות וניווט מקלדת (Tab על כותרות מתקפלות) בערכת נושא כהה ובהירה; חלון צר (עד 42em); אנגלית.
- בדיקה שהכפתורים במרכז חירום פועלים (העתקה ללוח, יצירת קודי גיבוי עם סיסמה).

`ui.errText` (ui.js) מציגה כעת הודעות ידידותיות בכל הטאבים; `ui.rawErrText` מחזירה את הטקסט הגולמי.
